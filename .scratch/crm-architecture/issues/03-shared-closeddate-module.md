# 03 — Shared `closedDate()` module — fix migration-script data corruption risk

**What to build:** `closedDate()` — "what date did this lead close" — is currently defined once in `index.html:1592` and re-derived independently in seven Node migration scripts, two of which (`betulkan-sales.mjs`, `fix-old-data.mjs`) disagree with the app (they force-overwrite to intake date instead of respecting a recorded close date) and will silently corrupt monthly sales attribution if run again. Move `closedDate()` into a new `domain/leads.mjs` ES module, imported by both `public/index.html` (via `<script type="module">`) and every migration script that needs it, so there is exactly one definition instead of one per file.

**Blocked by:** None — can start immediately

**Status:** done

- [x] `domain/leads.mjs` exports `closedDate(lead)` with unchanged logic: `closedAt || updatedAt || date || createdAt`. Module lives at `public/domain/leads.mjs` (not repo-root `domain/`) — Firebase Hosting only serves `public/` (`firebase.json` `"public": "public"` + a catch-all rewrite to `/index.html`), so a repo-root `domain/` would never reach the browser. Node migration scripts import it via `./public/domain/leads.mjs`.
- [x] `index.html` imports `closedDate`/`parseCRMDate` from `./domain/leads.mjs` via a `<script type="module">` block at the top of `<head>`, assigning them to `window.closedDate`/`window.parseCRMDate` so the rest of the legacy classic-script code can keep calling them as bare globals. Inline definitions removed.
- [x] `audit-leads.mjs` imports the shared `closedDate` instead of hardcoding its own fallback chain. `backfill-closedat.mjs` was evaluated and intentionally left as-is: its `pickCloseDate()` serves a different purpose (choosing what to *write* when `closedAt` is absent, with a "now" terminal fallback) rather than duplicating the *read* precedence, and it was never flagged as disagreeing with the app. `cleanup-agents.mjs`/`cleanup-dupes.mjs` don't reference `closedAt` at all — not applicable here (covered by ticket 05's `isDuplicateAgent`).
- [x] `betulkan-sales.mjs` and `fix-old-data.mjs`: per user decision, kept (not deleted) and defanged — both now skip any lead that already has a `closedAt`, so they can no longer force-overwrite a real recorded close date. `betulkan-sales.mjs` additionally gained the `DRY_RUN` preview guard it was missing.
- [x] `fix-old-data-backup.mjs` deleted (not reconciled) — code review flagged that after being hand-edited in lockstep with `fix-old-data.mjs`, the two files were still byte-for-byte identical, i.e. a duplicate with no unique content and a real risk of drifting apart on a future one-off edit. Git history preserves the pre-refactor version; no other file referenced it.
- [x] `betulkan-sales.mjs` and `fix-old-data.mjs` also now parse `entry` (`l.date || l.createdAt`) via the shared `parseCRMDate()` instead of a raw `new Date(entry)` — code review flagged the raw form as inconsistent with the parsing rigor `parseCRMDate` was introduced for elsewhere in this same change (handling Firestore Timestamp-shaped values), and as an unconditional `.toISOString()` that would throw before the `DRY_RUN` guard is even checked if `entry` weren't cleanly parseable. Confirmed via `index.html` that `date`/`createdAt` are always written as ISO strings today (never Firestore `Timestamp` objects), so this wasn't a live crash risk, but it removed the last quiet re-derivation of "how do we parse a raw date" and hardens against a future field-format change.
- [x] Unit tests for `closedDate()`/`parseCRMDate()` covering fallback precedence and date-parsing edge cases — `public/domain/leads.test.mjs`, 12 tests, run via `npm test` (`node --test`), no live Firestore connection. All passing (re-verified after the review fixes above).
- [x] No visible behavior change in the running app — verified in a real Chrome tab via claude-in-chrome: app loads, login screen renders identically, no console errors, `window.closedDate`/`window.parseCRMDate` are live functions with correct output. Full logged-in flows (add/edit/close a lead) need a real Firebase login and weren't exercised — this refactor doesn't touch that code path.
